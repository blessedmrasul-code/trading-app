# ARVEX V4 — аудит перед внедрением ARVEX PREMIUM

Дата: 2026-11-11  
Базовая ветка: `main`  
Рабочая ветка: `feature/arvex-premium-foundation`

## Что проверено

- `index.html`: статическая HTML-оболочка; подключаются `app.js`, `cloud-config.js`, `cloud.js`, школа и инструменты.
- `app.js`: профиль, баланс, позиции, история и прогресс хранятся в `localStorage` под ключом `arvex_v3_state`. Профиль создаётся локально по имени и username; подтверждённой серверной личности у него нет.
- `cloud.js`: есть отдельная необязательная авторизация по email/паролю и синхронизация через Supabase REST. Это не Telegram-авторизация и не система подписок.
- `cloud-config.js`: URL и anon key Supabase пустые; облачный вход по умолчанию не настроен.
- `netlify.toml`: публикуется корень репозитория; настройки Netlify Functions отсутствуют.
- `sw.js`: кэширует статические файлы; для новых клиентских модулей потребуется обновить список и версию кэша.
- В README описан `backend/supabase.sql`, но файл по этому пути в текущей ветке не найден.
- Поиск по репозиторию не обнаружил Telegram-бота, Telegram Web App auth, обработчиков платежей, Netlify Functions или существующей таблицы подписок.

## Выводы по безопасности

Нельзя выдавать PREMIUM по флагу в `localStorage`: его можно изменить вручную. Проверка срока и статуса подписки должна выполняться сервером. Оплата засчитывается только после подтверждённого Telegram Bot API события `successful_payment`; обработка должна быть идемпотентной по идентификатору платежа. Секрет бота нельзя помещать в клиентский JavaScript или Git.

## Согласованные продуктовые параметры

- 100 Telegram Stars (XTR) за 30 дней.
- Продление — отдельной оплатой в приложении; автоматического списания нет.
- После окончания срока платные возможности закрываются.
- Владелец получает бессрочный доступ администратора.
- Контакт на сайте: https://t.me/mrasulv

## Что требуется для полноценного запуска

1. Создать Telegram-бота через BotFather и получить токен; задать домен/URL Mini App или безопасный способ Telegram-аутентификации.
2. Определить Telegram numeric user ID владельца для серверного списка администраторов. Username сам по себе не является надёжным идентификатором доступа.
3. Настроить серверное хранилище (можно отдельную схему в Supabase) и применить SQL-миграцию.
4. Добавить Netlify Functions для создания invoice link, проверки Telegram Web App initData, webhook `pre_checkout_query`/`successful_payment`, статуса подписки и админских операций.
5. Добавить UI PREMIUM, привязанный к ответу серверного API, а не к локальному флагу.
6. Задать секреты в Netlify Environment Variables и установить webhook бота; проверить тестовые оплаты, повторные webhook-события, истечение срока и ручную выдачу доступа.

## Важное ограничение текущего этапа

В репозитории пока нет Telegram bot token, Telegram numeric user ID администратора, URL/ключей базы данных и настроенного Telegram Mini App. Поэтому безопасную реальную оплату и выдачу PREMIUM нельзя включить только изменением фронтенда. Этот аудит фиксирует фактическое состояние проекта и план реализации; он не заявляет, что платёжная система уже подключена.
