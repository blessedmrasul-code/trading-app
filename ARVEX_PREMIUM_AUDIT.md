# ARVEX V4 — аудит перед запуском ARVEX PREMIUM

Дата: 2026-11-11  
Основная ветка: `main`  
Рабочая ветка: `feature/arvex-premium-foundation`

## Подтверждённая архитектура

- Приложение — статический HTML/CSS/JavaScript, публикация через Netlify.
- Демо-состояние приложения хранится в `localStorage` под ключом `arvex_v3_state`.
- Облачная авторизация и синхронизация реализованы через Supabase Auth и таблицу `public.arvex_saves`.
- PREMIUM хранится на сервере в `public.arvex_subscriptions`; выдача и отзыв доступа выполняются защищёнными Supabase RPC.
- Клиентский publishable key Supabase публичный по назначению; секретные ключи нельзя помещать в браузерный код или Git.
- Владелец вручную проверяет получение Telegram Stars и вручную выдаёт доступ из админ-панели. Telegram-бот, Telegram Mini App и автоматическая обработка платежей в согласованную первую версию не входят.

## Согласованная модель продажи

- Цена: 100 Telegram Stars за 30 дней.
- Покупатель самостоятельно переводит Stars владельцу `@mrasulv`.
- Кнопка на сайте открывает `https://t.me/mrasulv`.
- После проверки перевода владелец вручную находит облачный аккаунт покупателя и выдаёт 30 дней PREMIUM.
- Продление — отдельной ручной выдачей после нового перевода; автосписаний нет.
- Администратор может выдать 30, 90, 365 дней или бессрочный доступ, а также отозвать подписку.
- Владелец получает бессрочный доступ после создания облачного аккаунта и назначения его администратором.

## Выполненные дополнительные меры

- Исправлена синхронизация: более старая облачная копия не должна перезаписывать локальное состояние с более поздним `updatedAt`; добавлены регрессионные тесты для обоих направлений синхронизации и равных временных меток.
- В админ-панели добавлено подтверждение перед выдачей PREMIUM с напоминанием подтвердить перевод Stars; поиск не запускается с пустым или слишком коротким запросом.
- В SQL-функции выдачи подписки добавлена явная проверка `p_days IS NULL`, чтобы некорректный вызов не мог создать подписку без срока действия.
- Исправление SQL применено в Supabase миграцией `arvex_validate_subscription_duration` (версия `20261111160608`) и проверено чтением фактического определения функции.
- Добавлены GitHub Actions проверки синтаксиса JavaScript, локальных ссылок ресурсов, манифеста, клиентских ключей, связки PREMIUM RPC и тестов синхронизации.
- Версия кэша Service Worker обновлена до `arvex-v4-7`.

## Ограничения, которые нужно закрыть до запуска

1. Локальный профиль по имени и username не является серверной личностью. Для ручного назначения подписки покупатель должен зарегистрировать облачный аккаунт по email и войти в него.
2. В Supabase на момент последней проверки нет зарегистрированных пользователей. Поэтому администратор ещё не назначен и реальные операции выдачи PREMIUM не проверены.
3. Для назначения владельца администратором нужен UUID его облачного аккаунта из Supabase Auth. Пароль и секретные ключи никому передавать не нужно.
4. Проверить на Preview: регистрацию, подтверждение email (если включено), вход, синхронизацию, отображение статуса PREMIUM и админские RPC.
5. Проверить мобильную вёрстку, повторный вход, истечение подписки и ручную выдачу/отзыв доступа.

## Результат повторной проверки Supabase

- Health Advisor: замечаний нет.
- Security Advisor: 2 INFO по закрытым RLS-таблицам `arvex_admins` и `arvex_subscription_events` (политик нет намеренно, прямой доступ ролям клиента закрыт); 7 WARN о доступности SECURITY DEFINER RPC роли `authenticated`. Эти RPC нужны клиенту, но административные функции проверяют `auth.uid()` по `arvex_admins`; `arvex_my_premium()` возвращает только подписку текущего пользователя. Предупреждения лinter остаются видимыми и требуют повторной проверки после появления тестовых аккаунтов — не считаем их автоматически устранёнными.
- Performance Advisor: 3 INFO о пока неиспользуемых индексах. Таблицы пустые, поэтому по этим сообщениям индексы удалять нельзя.

## Безопасность и границы первой версии

- PREMIUM нельзя определять по флагу в `localStorage`; источник статуса — серверная функция `arvex_my_premium()`.
- Админские RPC проверяют наличие текущего пользователя в `public.arvex_admins`.
- Не хранить токены Telegram-ботов, service_role или другие секреты в клиентском JavaScript.
- Перевод Stars проверяется владельцем вручную; приложение не заявляет об автоматической проверке платежа.
- До проверки Preview и Supabase не объединять рабочую ветку с `main` и не публиковать её в Production.
